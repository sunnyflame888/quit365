## 迁移流程

1. 在原来记录的iPhone Safari或主屏幕模式中导出加密备份，私密保存并确认密码可用；不要先清除网站数据。
2. 更新应用静态版本，确认能读到原本日志；数据库名称和state键保持不变。
3. 登录指定GitHub账户，先查看本机/云端记录数量与冲突；登录本身不会自动上传V1.0数据。
4. 确认备份，明确选择同日和settings冲突，再点“合并并开启同步”。迁移前原始本机状态额外保留快照。
5. 等待“已同步”，然后在第二设备登录、预览并开启。同步失败或中断保留本机数据，可安全重试。
6. 大于1MiB的有效本机日志仍可保存、导出；当前云端文档拒绝上传，不截断或删旧记录。扩容需受控升级后再同步。

## 回滚及误操作恢复

- PR未合并：生产站完全没有改变；停止预览，保留分支和私有仓库即可。
- 已上线后回滚：先从每台有未同步编辑的设备导出备份，停止自动同步。将前端回退至V1.0.3，但使用新的Service Worker缓存版本发布，避免旧缓存继续显示V1.1。不要通过清除网站数据更新应用。
- V1.1仍保存schemaVersion=1；V1.0能读取已同步的本机日志及可忽略的urge id字段。只回退前端不会自动取回“只在另一台设备上”的数据，须先完成同步/备份。
- 设置→跨设备同步→查看本机恢复快照，可导出迁移前、导入前或清空前版本，核对后用原JSON恢复入口恢复。恢复会停止自动同步，需再次预览后才能上传。
- 清空本机仅清当前使用状态并断开同步，保留云端与本机恢复快照；不会作为云端删除指令。真正清除所有隐私副本还需本人处理快照/浏览器数据/独立备份及私有Git历史，不能误称按钮已经擦除全部历史。
- 云端恢复旧Git版本须先导出当前云端和各设备未上传状态，由本人明确选择目标版本，再用当前SHA条件写入；不能直接强推旧分支或自动覆盖当前数据。
- PAT或Worker被停用时仍可本地记录和导出；修复配置后登录并处理积累的冲突。
